# Trade Unit by Defo — калькулятор малого товарного бизнеса

Автор: [Defo](https://portfolio.defo-tech.shop/).

Статичный сайт: считает, во сколько обходится товар, сколько остаётся с набора и заказа и чем закончится
месяц магазина после рекламы и накладных расходов. Для одного предпринимателя (оборот до ~$250 тыс. в год),
который закупает товары в Китае или делает сам и продаёт поштучно или наборами.

Бэкенда нет. Всё считается в браузере, данные лежат в браузере (localStorage) и сохраняются в файл JSON.
Интерфейс на русском.

> **Агенту:** сначала прочитай этот файл целиком, потом `AGENTS.md` (правила работы), потом
> `ARCHITECTURE.md` (модель данных и формулы). `VISION.md` — зачем продукт устроен именно так,
> `TAXES.md` — налоговые пресеты и источники цифр.

## Установка из репозитория (для агента)

Пользователь прислал ссылку на репозиторий и просит установить сайт на его компьютер. Порядок:

1. Проверь Node.js: `node -v` должно быть 20.19 или новее (подойдёт и 22.12+). Если Node нет или он старый, поставь актуальную LTS-версию с nodejs.org (или через менеджер версий) и скажи об этом пользователю.
2. Скачай и установи:
   ```bash
   git clone <ссылка на репозиторий> trade_unit
   cd trade_unit
   npm install
   ```
3. Проверь, что всё в порядке: `npm test` (тесты расчётов зелёные) и `npm run build` (без ошибок).
4. Запусти: `npm start`. Он собирает сайт и поднимает его на `http://localhost:4317`. Открой этот адрес в браузере и покажи пользователю. Порт зафиксирован: данные в браузере привязаны к адресу, при смене порта они «пропадут».
5. Скажи пользователю три вещи: данные хранятся только в его браузере (в localStorage); чтобы их не потерять, нужно сохранять учётную запись в файл (вкладка «Настройки», кнопка «Сохранить в файл»); при каждом новом запуске достаточно `npm start` в этой папке.

Обновить до новой версии: `git pull`, затем `npm install` и `npm start`. Свои правки под пользователя вноси, прочитав `AGENTS.md`.
Сайт ничего не отправляет в интернет: бэкенда нет, нет аккаунтов и ключей. Сеть нужна только для установки и для кнопки «Обновить курсы».

## Запуск

Нужен Node.js 20.19 или новее (подойдёт и 22.12+). Проверить: `node -v`.

```bash
npm install        # один раз
npm run dev        # разработка: http://localhost:5173
npm test           # тесты расчётов
npm run build      # проверка типов + сборка в dist/
npm run preview    # посмотреть собранный dist/: http://localhost:4173
npm start          # собрать и запустить на фиксированном адресе http://localhost:4317
```

Важно знать:

- **Данные привязаны к адресу.** `localhost:5173` (dev) и `localhost:4173` (preview) для браузера разные
  сайты, у каждого своя база. Если «пропали» данные, скорее всего открыт другой адрес.
- **Файл `dist/index.html` двойным кликом не откроется** (браузер блокирует модули с `file://`).
  Открывайте через `npm run preview` или любой статичный сервер.
- Пока нет интернета, не работает только кнопка «Обновить курсы». Остальное работает без сети.

## Что умеет (вкладки)

| Вкладка | Что делает | Файл |
|---|---|---|
| Товары | Выбор товара кнопкой со списком. Карточка товара: области расходов с номерами (1 закупка у поставщика, 2 доп. расходы, 3 доставка по Китаю, 4 доставка основная (из Китая в страну и по стране до склада), 5 таможня, 6 упаковка) и справа таблица «Из чего складывается» по тем же областям | `src/tabs/ProductsTab.tsx` |
| Наборы | Каждый набор на всю ширину: слева состав, справа упаковка, цена, маржа, наценка, скидка и сколько соберётся из наличия | `src/tabs/KitsTab.tsx` |
| Каналы продаж | Каждый канал на всю ширину: реклама (готовая цена заказа в деньгах или процентом от оборота, либо воронка CPM, CTR, конверсия), апрув, выкуп, и справа «Что нужно для продажи» (по умолчанию для одной, число можно вписать): сколько показов, кликов, заказов, подтверждений, цена каждого и итог | `src/tabs/ChannelsTab.tsx` |
| Магазин | План продаж на месяц, доли позиций (товаров и наборов) и доли каналов, что получается по позициям (с процентами от оборота), накладные расходы (сумма в месяц, процент от оборота или сумма за штуку: доставка, упаковка, хранение, комиссии), итог: оборот, себестоимость, реклама, прибыль до и после накладных | `src/tabs/StoreTab.tsx` |
| Аналитика | План магазина за день, неделю или месяц: десять главных показателей (оборот, продано, средний чек, маржинальность, отдача рекламы, накладные, чистая прибыль, рентабельность, прибыль с заказа, окупаемость затрат), куда уходит оборот, прибыльность по позициям и каналам (деньги и качество: оборот, маржа, реклама, прибыль, прибыль с заказа и их проценты от оборота), накладные расходы. Вверху переключатели «Сейчас / Прогноз» и «День / Неделя / Месяц / Свой» (свой срок: число и единица в окне, дни, недели или месяцы): «Сейчас» показывает расчёт по настоящим данным, «Прогноз» пересчитанную картину, они не смешиваются на одном экране. Справа в «Сейчас» список показателей, в «Прогнозе» «Что можно менять»: текущие значения в отдельных областях (план; товары и наборы: цена и себестоимость; каналы продаж: CPM, CTR, конверсия, апрув, выкуп; накладные расходы), колонка прогноза, от неё всё пересчитывается, и колонка изменения в процентах к текущему; кнопка «Сбросить» очищает прогноз | `src/tabs/AnalyticsTab.tsx` |
| Настройки | Сверху учётные записи (несколько независимых наборов данных, сохранение в файл и открытие из файла), ниже основная валюта, курсы (с кнопкой обновления из центробанков и наценкой) и налоговый режим | `src/tabs/SettingsTab.tsx`, `src/tabs/AccountsTab.tsx` (карточка записей) |

**Учётная запись** — отдельная база: свои товары, наборы, каналы, магазин и настройки. Новая запись
создаётся пустой (ничего не подставляется). Файл JSON — это ровно одна учётная запись.

src/
  main.tsx         запуск React
  App.tsx          вкладки, учётные записи, сохранение
  styles.css       все стили и дизайн-токены (:root)
  demo.ts          пример с данными, пустая база, заготовки товара и канала

`src/engine/` — главное место проекта, все формулы только там:

| Файл | Что внутри |
|---|---|
| `types.ts` | Все структуры данных (товар, набор, канал, план, налоги, база) |
| `money.ts` | Перевод между валютами, наценка обменника |
| `product.ts` | Себестоимость партии по шагам, платный вес, импортный НДС, разбивка по областям |
| `channel.ts` | Рекламная воронка, экономика заказов: оборот, себестоимость, реклама с апрувом и выкупом |
| `offers.ts` | «Предложение» = товар поштучно или набор; себестоимость набора, лимит по остаткам |
| `store.ts` | Месяц магазина: план продаж → доли позиций → доли каналов → оборот, себестоимость, реклама, прибыль, накладные расходы |
| `analytics.ts` | Прогноз («что будет, если...»): подмена значений поверх копии базы, итоги для вкладки «Аналитика» |
| `taxes.ts` | Налоги выбранного режима; `calcStore` включает их в накладные расходы магазина |
| `taxPresets.ts` | Налоговые режимы-заготовки |
| `engine.test.ts` | Тесты (Vitest) |

## Как делать правки

Интерфейс не считает ничего сам: вкладки показывают то, что вернул движок. Поэтому:

- **Меняется формула или логика** → правка в `src/engine/`, тест в `engine.test.ts`, потом интерфейс.
- **Меняется только вид или текст** → `src/tabs/`, `src/ui/kit.tsx`, `src/styles.css`.
- **Нужно новое поле у товара, канала или в настройках** → цепочка шагов описана в `ARCHITECTURE.md`,
  раздел «Типовые правки». Главное правило: старые сохранённые данные не должны ломаться.

Перед тем как считать работу сделанной: `npm run build` без ошибок, `npm test` зелёный, правка
посмотрена в браузере, документы обновлены, если поменялась логика или структура.

## Сборка и выкладка

Сборка даёт обычные статичные файлы в `dist/`. Сервер приложению не нужен, базы данных нет:

```bash
npm run build
# папку dist/ можно положить на любой статичный хостинг или за nginx
```

Адреса вкладок — через `#` (например, `/#store`), поэтому настройка «все пути на index.html» не нужна.
Данные каждого пользователя остаются в его браузере, на сервере ничего не хранится.
Сайт ходит в сеть только за курсами валют (Европейский центробанк через api.frankfurter.dev,
Национальный банк Украины, Центральный банк Узбекистана), ключей не требуется.
