# VISION — Trade Unit: калькулятор товарного бизнеса

> Источник правды по продукту. Решения о продукте принимает владелец проекта; правки формулировок делаются без изменения смысла. Документ описывает продукт на момент передачи (01.10.2026), дальше владелец своей копии правит его под себя.
> Согласовано в диалоге 01.10.2026.

## Цель

Инструмент моделирования для малого товарного бизнеса: один предприниматель (ФОП, ЕООД, ИП),
оборот до ~$250k в год. Человек ищет товары в Китае или производит сам и решает:

- во сколько обходится штука с учётом всей цепочки до склада;
- продавать поштучно или собирать наборы из того, что уже есть;
- через какие каналы, с какой рекламой и ценой;
- сколько магазин зарабатывает за месяц после всех расходов и налогов, где точка безубыточности
  и какой рычаг двигает прибыль сильнее всего.

## Пользователи и масштаб

- Владелец и 1–2 знакомых. Не публичный продукт: без регистрации, без сервера, без ролей.
- До 50–100 товаров в каталоге.
- **Масштабирование в будущее не закладываем.** Просто и надёжно.

## Вкладки

| Вкладка | Что делает | Результат |
|---|---|---|
| **Товары** | Каталог. Карточка товара = расчёт себестоимости партии: закупка, логистика в стране, международная доставка, таможня, упаковка штуки, брак. Происхождение «импорт» или «своё производство» (без фрахта и таможни). | Себестоимость 1 шт., деньги на партию, остаток, базовая цена продажи |
| **Наборы** | Набор собирается из товаров каталога + упаковка набора + цена. | Себестоимость и маржа набора; сколько наборов собирается из остатков |
| **Каналы продаж** | Общий справочник каналов: реклама для каждого источника: готовая цена (суммой за заказ или процентом от оборота, как у маркетплейса) либо воронка CPM → CTR → конверсия сайта → апрув → выкуп. Доставка, возвраты и комиссия не здесь, а в накладных расходах «Магазина». | Что нужно для продажи (для одной или для вписанного числа): сколько показов, кликов, заказов, цена каждого и итог по рекламе |
| **Магазин** | Сколько продаж за месяц; какая доля приходится на каждый товар и набор; как доля позиции делится между каналами; накладные расходы (сумма в месяц, процент от оборота или от рекламы, сумма за штуку). | Оборот, себестоимость, реклама, прибыль до накладных и после них |
| **Аналитика** | Тот же план магазина в разрезе дня, недели и месяца: главные показатели, куда уходит оборот, прибыльность по позициям и каналам, накладные расходы. Переключатель «Сейчас / Прогноз» разводит настоящий расчёт и прогноз по разным экранам. Справа показатели, на которые можно влиять: в «Прогнозе» рядом с текущим значением колонка для нового значения и изменение в процентах; впишите другое значение (рекламу, апрув, цену, себестоимость, план) и вся аналитика пересчитается; «Сбросить» возвращает базовые значения. Расчёт по плану, фактических продаж пока нет. | Чистая прибыль, рентабельность, прибыль с заказа, сравнение «сейчас» и «прогноз» |
| **Настройки** | Учётные записи: создать, переименовать, открыть, удалить, сохранить в файл и открыть из файла. Ниже валюта, курсы, налоговый режим. | — |

### Ключевое правило разделения расходов

- Карточка товара — только то, что относится к партии и штуке (себестоимость).
- Накладные бизнеса (склад, комплектовщик, сервисы, бухгалтер) — только в «Магазине», за месяц.
  Иначе при нескольких товарах склад считается несколько раз.
- Расходы на отправку заказа (коробка, скотч) — в «Магазине», за отправку.

## Налоговые режимы — только базовые

Пресеты заполняют параметры, все параметры видны и редактируются. Цифры 2026 года и источники —
`TAXES.md`.

| Страна | Режимы |
|---|---|
| Болгария | ЕООД без ДДС; ЕООД с ДДС 20% |
| Украина | ФОП 2 группа; ФОП 3 группа 5%; ФОП 3 группа 3% + ПДВ |
| Узбекистан | ИП, налог с оборота 1%; ООО, налог с оборота 4%; общий режим: НДС 12% + налог на прибыль 15% |

Плюс «свой режим» — те же поля, заполненные вручную.

## Что сознательно НЕ делаем

- Лимиты выручки налоговых режимов: калькулятор их не проверяет (решение 01.10.2026).

- Учётную систему: партии FIFO, мультисклады, движение товара по документам, интеграции с CRM.
- Полный каталог налоговых систем, зарплатные налоги сотрудников, НДС-нюансы (частичный зачёт,
  обратное начисление на рекламу, SME-режимы ЕС).
- Сервер, базу данных, авторизацию, многопользовательский доступ.
- Кэшфлоу «Деньги» (когда платишь за партию и когда возвращаются деньги) — **вторая очередь**.

## Хранение и учётные записи

Всё в браузере (localStorage) с автосохранением. Данные разложены по **учётным записям**: учётная
запись — это свой набор товаров, наборов, каналов, магазина и настроек (решение 01.10.2026).

- Учётные записи переключаются, создаются, переименовываются и удаляются; последнюю удалить нельзя.
- **Новая учётная запись пустая:** без товаров, каналов, расходов, налогов и курсов. Значения по
  умолчанию не подставляются, человек заполняет сам. Основная валюта новой записи — USD: это
  единственная валюта, которой не нужен курс.
- При первом запуске создаются две учётные записи: «Тест-пример» с готовыми данными (открыта) и «Пустая». Образец можно добавить ещё раз кнопкой «Добавить пример».
- **Файл JSON = одна учётная запись.** «Сохранить в файл» сохраняет открытую запись, «Открыть файл»
  добавляет запись из файла как новую и ничего не перезаписывает. Старые файлы без обёртки тоже открываются.
- Надёжность — регулярное сохранение в файл; приложение показывает, когда запись сохраняли последний раз.
- Если для валюты, которая используется в расчётах, не задан курс, сверху висит предупреждение.

Курсы валют обновляются кнопкой из официальных открытых источников, каждая валюта у своего
центробанка: EUR и CNY у ЕЦБ, UAH у НБУ, UZS у ЦБ Узбекистана (решение 01.10.2026). К курсу банка
добавляется видимая и редактируемая наценка обменника (по умолчанию 2%): каждая валюта, кроме основной,
становится на неё дороже, чтобы закупка и расходы считались с запасом. Чистый курс банка виден под полем.

Области на всех вкладках сворачиваются; какие свёрнуты, браузер запоминает (одинаково для всех учётных записей).

## Технические решения

- Статичный сайт: Vite + React + TypeScript, без бэкенда. Деплой — папка `dist/` за nginx.
- Расчётный движок (`src/engine/`) — чистые функции без интерфейса, покрыт тестами (Vitest).
  Тесты фиксируют числа: изменилась цифра — у изменения есть причина.
- Внутри всё считается в основной валюте; курсы задаются как «сколько единиц валюты за 1 USD».

## Критерий готовности v1

Открыть сайт (`npm run dev` или собранный `dist/`) и пройти сценарий:

1. Во вкладке «Товары» завести товар, поменять закупку и фрахт — себестоимость 1 шт. пересчитывается.
2. Во вкладке «Наборы» собрать набор из двух товаров — видна себестоимость, маржа, сколько наборов
   собирается из остатков, прибыль с заказа по каналам.
3. В «Каналах продаж» переключить канал на воронку CPM/CTR/CR — CPA считается и подтягивается в расчёты.
4. В «Магазине» задать план продаж, распределить его по позициям и каналам, добавить накладные расходы — видны оборот,
   себестоимость, реклама, прибыль до и после накладных. Больше 100% вписать нельзя.
5. В «Настройках» переключить налоговый режим (BG/UA/UZ). Налоги режима автоматически входят в накладные расходы магазина и уменьшают чистую прибыль.
6. Экспорт JSON → очистить данные → импорт JSON — всё вернулось.
7. `npm test` — зелёный.
